# NewAPI Check-in Pages

独立的公开配置前端。这个仓库只托管网页，不包含签到程序、真实账号配置、
`.env`、PAT、Actions Secrets 或原私有仓库的 Git 历史。

## 启用免费 GitHub Pages

1. 将本目录作为全新的公开仓库推送到 GitHub，不要 fork 或公开原私有仓库。
2. 在公开仓库的 `Settings` → `Pages` 中，将 Source 设为 **GitHub Actions**。
3. 在 `Actions` 手动运行 **Deploy configuration UI to GitHub Pages**，选择默认分支。
4. 部署成功后打开 Pages 站点的 `/config_generator.html`，无需运行本地服务。

部署只发布 `scripts/build_pages.py` 中的静态文件白名单，不上传整个仓库。
首次部署前需先设置 Pages 来源；后续网页更新会自动部署。

## 修改私有配置仓库

1. 点击账号管理区的「设置 → GitHub」，填写连接信息。
2. 填写原来的**私有配置仓库** `owner/repo`，不是这个公开前端仓库。
3. 输入仅授权私有配置仓库的 Fine-grained PAT，授予 Contents、Workflows、
   Secrets 的 Read and write 权限；组织仓库可能需要管理员批准。
4. 点击「保存设置」，关闭弹窗并自动加载远端账号，再添加账号并填写新增或更新的令牌。
5. 点击主界面的「GitHub 同步」直接保存，自动合并账号 JSON、更新两个签到工作流并加密上传账号 Secrets。

账号表格每行一个账号，支持搜索、分页和弹窗增删改；表格只显示令牌填写状态。
「同步状态」区分已同步、新增未提交、修改未提交；已同步以最近一次 GitHub 加载或全部保存成功为准。
改动恢复为原值后恢复已同步，填入新令牌也算待提交修改；部分保存失败会保留草稿和待提交标记。
启用账号默认排在停用账号前，同组保持原有顺序；搜索、分页和切换启停均沿用该排序，导出仍包含全部账号。
桌面内容区最大宽度为 1480px，表格缩小行间距以显示更多账号；窄屏保留横向滚动和单列编辑表单。
翻页和筛选不会缩小配置保存范围。编辑仅更新当前草稿，不自动保存到浏览器或 GitHub。
删除账号或修改站点 / 用户 ID 后，先确认已加载完整列表，再选择「替换账号列表」保存。

PAT 不写入网页源码或项目文件。默认仅在本页使用，也可按下节选择加密保存。浏览器直连 GitHub API，
加密库随站点发布，不经过第三方代理。仅在自己控制的可信页面输入凭证。
远端私有仓库需要已有 `accounts.config.json` 和两个签到工作流。

## 分类设置与常用操作

设置分为「GitHub」「通知与续期」「WebDAV」「数据工具」。GitHub 与通知共用连接保存，WebDAV 单独保存；切换分类不会丢失输入，取消关闭会恢复未保存选项。
日常入口保留添加账号、刷新账号、GitHub 同步、WebDAV 同步、设置及当前 PAT 的锁定 / 解锁。
生成配置、浏览器草稿、批量导入、书签工具和实时查询在「数据工具」中使用。重复的加载、确认保存、展开 / 收起按钮已合并；删除远端账号的替换操作仍需确认。

## 启用与停用签到

账号表格的「已启用 / 已停用」开关和编辑弹窗的「启用签到」复选框控制单个账号。
新增账号及未填写 `enabled` 的旧配置默认启用；停用会保存为 `"enabled": false`。
修改只更新当前草稿，点击「GitHub 同步」成功后，后续定时任务才采用新的状态。

停用保留账号、Secret 引用和工作流映射，不删除 Secrets。可以保存暂未配置 Secret 的停用账号；
重新启用时必须已有对应 Secret 或填写令牌。配套签到程序跳过停用账号的所有站点请求及附加任务，
不将其计为失败；全部停用时正常结束。搜索、分页和导入导出都会保留启用状态。

## VyceAI 每日奖励

在「添加账号」弹窗选择「VyceAI 每日奖励」，填写站点、备注及 SessionToken，无需 NewAPI 用户 ID。
默认站点为 `https://vyceai.com`，SessionToken 使用已登录网站的 `session` Cookie 值。
每个账号自动分配稳定的 `account_id` 和独立的 `VYCEAI_SESSION_TOKEN_…` Secret 名，
修改备注或轮换令牌时保留账号标识。公开 JSON 仅包含 `type: "vyceai"`、站点、标识、备注、
启用状态及 `session_token_env` 引用，SessionToken 通过「同步 Secrets」加密上传。

编辑已有账号时令牌留空会保留远端 Secret，其值不会读回页面。删除账号后选择「替换账号列表」保存；
允许删除最后一个账号并保存空列表，删除账号不会自动删除已有 Secrets。
NewAPI 和 VyceAI 可混合管理，也可分别停用。旧版简单格式不能表达 VyceAI 或停用状态，请使用 JSON。

## TokenBom 积分签到与自动续期

在「添加账号」选择「TokenBom 积分签到」，默认地址为 `https://tokenbom.com`，填写网站的 **refreshToken**，无需用户 ID。
默认变量名 `TOKENBOM_REFRESH_TOKEN_ACCOUNT…` 会直接填入输入框，可在此基础上修改。
保存时检查全表变量名冲突，包括停用账号和其他分页中的账号；切换类型只更新未修改的默认名称。
公开配置使用 `type: "tokenbom"`、稳定的 `account_id` 及 `refresh_token_env`，不会包含实际令牌。

TokenBom 可能在刷新 accessToken 时轮换 refreshToken。启用 TokenBom 后点击「GitHub 同步」，
若仓库尚无 `TOKENBOM_SECRETS_PAT`，页面会自动使用当前连接 GitHub 的 PAT，加密保存为该 Secret，
供后续任务把轮换后的 refreshToken 和 accessToken 缓存一并写回原账号 Secret，无需重复填写 PAT。
当前 PAT 需要具有私有签到仓库的 **Secrets: Read and write** 权限；默认 `GITHUB_TOKEN` 不具备修改仓库 Secrets 的权限。
已有续期 Secret 时会保留，不会因更换网页连接 PAT 而覆盖，也不会从 GitHub 读回凭证。
如需使用独立 PAT 或更换续期凭证，可在「设置 → 通知与续期 → TokenBom 自动续期 PAT」中填写，单独填写的值优先。

点击「保存设置」只保留本页的续期草稿，再点击「GitHub 同步」才加密上传并更新两个工作流映射。
续期 PAT 不写入账号 JSON、`.env` 或额外的浏览器存储；普通账号草稿和加密记住网页 PAT 的功能保持独立。
启用 TokenBom 必须具备 refreshToken，并开启自动同步 Secrets；仅有停用的 TokenBom 账号时不会自动保存连接 PAT，也不会刷新或访问站点。

配套签到程序在 GitHub Actions 中执行，复用有效期还剩 10 分钟以上的 accessToken，
缓存缺失、临近过期或缓存令牌被状态接口以 401 拒绝时才刷新，每次运行最多刷新一次。
原账号 Secret 同时保存 refreshToken 和 accessToken 的版本化 JSON 缓存，下一次任务通过原有工作流映射加载；
旧的纯 refreshToken 无需迁移，首次成功刷新后自动建立缓存，不新增 Secret 或账号字段。
在 Pages 编辑账号时，令牌留空保留远端缓存；重新填写 refreshToken 会替换原 Secret、清除旧缓存。
缓存绑定站点地址，更换站点后需要填写对应站点的 refreshToken。缓存不回传网页，不写入文件、日志或构建产物。

仅在需要刷新时，用无凭证的固定值创建 / 更新 `TOKENBOM_WRITE_CHECK` 检查写权限，
再获取 accessToken；两种令牌通过一次加密 Secret 写入保存成功后才继续签到，临时写入失败最多尝试三次。
缓存有效的运行仍检查仓库私有性，但不写 Secrets。JWT 无有效到期时间或缓存过大时仅保存 refreshToken，下一次正常刷新。
请勿将这两个管理 Secret 名用作账号变量名。任务中断或轮换令牌持续保存失败时，需重新登录 TokenBom 并更新 refreshToken。
不支持缺少该持久化机制的本地运行，也不要在其他脚本中并发使用同一 refreshToken。
站点要求当天先完成 API 调用时会提示，不代为发起付费调用；明确成功后不额外查询状态，结果不明确时只读复核，不重复提交签到。

## 记住 GitHub 设置与 PAT

在「设置」弹窗填写签到配置仓库、分支、合并/替换方式及保存选项，然后点击「保存设置」。
设置保存在当前浏览器，保存成功后关闭弹窗；取消、关闭或按 Esc 会丢弃尚未保存的设置输入。
首次设置、切换仓库或分支后会自动读取 GitHub 账号；仅修改保存选项不会重新加载或覆盖当前草稿。
主动打开设置时，保存只保存连接信息；账号修改仍需点击「GitHub 同步」。如果由同步按钮触发补充配置，保存后继续原来的同步，不先加载覆盖当前草稿。

需要记住 PAT 时，勾选「用自设密码加密记住 PAT」，填写 PAT 和至少 5 个字符的密码，
重复密码后保存。刷新或重新打开页面会自动弹出解锁框，输入密码并点击「解锁 PAT」，
启动时随后读取已配置仓库 / 分支的最新账号；同步中解锁则直接继续该次同步，不覆盖草稿。解锁框只有一个密码输入，不展示完整设置。
未加密记住 PAT 时，重新打开页面需要重新填写 PAT。
可随时立即锁定、删除 PAT 密文，或清除整套 GitHub 设置；这些操作不会撤销 GitHub 上的 PAT。
修改加密密码需先解锁或重新填写 PAT，再输入新密码及确认密码保存。
忘记密码无法恢复密文，请删除后重新填写 PAT。临时不加密保存的 PAT 不保证刷新后保留。

表格旁的「刷新账号」随时重新读取 GitHub 最新账号。当前账号有编辑、导入、删除或待保存的
PushPlus 设置时，会先确认是否覆盖；取消或加载失败会保留当前表格。搜索、翻页不请求 GitHub。
加载只读取账号元数据，不读回 `.env` 或 Secrets 的值，已有账号不必重新填写令牌。
从书签打开页面时，先完成账号加载或取消解锁，再显示添加账号弹窗，避免导入被加载操作打断。

密文保存在当前来源的 localStorage，使用 AES-GCM-256 和 PBKDF2-SHA256（600,000 次），
每次加密生成独立随机盐和 IV；密码和解密密钥不保存。不同域名、浏览器或设备不共享设置。
普通 JavaScript Cookie 也能被同源脚本读取，还会随请求发送，因此这里不使用 Cookie 保存 PAT。
加密保护浏览器存储中的内容；无法防止可信页面被篡改、恶意扩展或解锁期间的同源恶意脚本。
请使用独立强密码，且仅在自己控制的 HTTPS 页面输入 PAT。

账号草稿及 WebDAV 连接信息是独立功能，不受 PAT 加密保护。
包含账号凭证的草稿和记住 WebDAV 密码时，会先明确提示明文存储并要求确认。

## PushPlus 结果推送

在 HTTPS 配置页的「设置 → 结果推送 · PushPlus」中，
选择「启用 / 更新」，填写 PushPlus Token，保持「自动创建 / 更新 Actions Secrets」勾选，
先点击「保存设置」，再在页面确认保存到 GitHub。Token 只加密上传为 `PUSHPLUS_TOKEN` Secret，不写入账号 JSON、
工作流明文、`.env` 或浏览器存储。目标仓库已有同名 Secret 时可留空。
首次缺少 Token 会在写入任何文件或 Secrets 前停止；全部保存成功后清空页面中的推送凭证，
部分失败时保留当前页面草稿供核对重试。

保存将向两个签到工作流添加独立通知步骤，通过 HTTPS 调用 PushPlus；
无需复制或修改签到程序，也不会在保存配置时发出通知。
后续签到步骤成功或失败时，推送任务状态和 Actions 日志链接；
可以选择仅失败推送，被取消或跳过的签到步骤不发送。
推送失败不覆盖签到步骤结果，接口接受消息不等于最终送达，不自动重试以避免重复通知。

这里支持的是**任务级结果**，不收集或发送账号令牌、完整日志、逐账号余额或签到明细。
若签到程序在部分账号失败时仍正常退出，任务状态会显示成功，逐账号结果需查看日志。
默认「保留现有推送设置」不会改动通知；「关闭」只删除本页面添加的通知步骤，
保留已有 Secret 和其他渠道。再次启用时请重新选择推送范围。
此配置暂只支持 HTTPS 浏览器 / Pages 模式，本地 `/github-config` 后端需单独升级。

「设置」统一包含 GitHub 连接、推送及 TokenBom 续期配置。取消或关闭弹窗会恢复打开前的推送及续期草稿；
保存设置后未上传的改动会在设置摘要中标识。推送和续期凭证仅暂存在本页，刷新会丢失，需保存到 GitHub 后才生效。

## 添加账号、导入与书签

- 单账号导入在「添加账号」弹窗内：点击「从剪贴板填入」，或展开「手动粘贴单账号 JSON」。
  支持单个账号对象、只含一个账号的数组及只含一个账号的站点分组配置。
  导入只预填弹窗，检查后点击「保存到表格」，不会直接覆盖账号表或自动保存凭证。
- 同站点 URL + 用户 ID 的账号已存在时，会提示打开其编辑弹窗；缺省的变量名及凭证保留原值。
  同站点不同用户 ID 是不同账号，新账号未填写变量名时会分配独立名称。
- 主页面「批量导入 JSON」支持平铺数组和站点分组配置，默认合并并保留其他账号；
  只有明确选择并确认替换才移除草稿中的其他账号。全部账号校验通过后才更新草稿，
  变量名冲突或无效账号不会留下部分导入结果。替换后保存到 GitHub 需选择「替换账号列表」。
- 剪贴板权限不可用时，可在弹窗手动粘贴。关闭弹窗会清除其中的导入文本；
  剪贴板请求期间关闭或切换弹窗，不会把延迟返回的数据填入新的弹窗。
  书签代码无法自动复制时，也可在同一弹窗内手动复制，无需关闭弹窗或丢弃已填写内容。

站点抓取书签也已适配账号表。更新页面后，需要重新拖拽或复制新版书签：

1. 在已登录的 NewAPI 站点点击书签，先确认重新生成系统访问令牌的风险；旧令牌会失效。
2. 抓取结果复制为单账号 JSON；自动复制失败时，会提供手动复制方式。
3. 切回已有配置页，在「添加账号」中填入并检查，保存到表格，再统一保存到 GitHub。
   如没有已有草稿，也可在书签提示中选择打开新配置页。请勿重复抓取后忘记更新令牌。
   浏览器可能拦截新窗口，此时请手动切回或打开配置页。

新版书签不把令牌放进配置页 URL，不自动暂存或保存到浏览器，也不自动修改 GitHub。
旧版 `#bm=` 链接仍可接收：立即清除地址栏数据，只在当前页面保留待确认账号；
单账号预填弹窗，多账号可逐个确认或主动合并到草稿，按 URL + 用户 ID 区分。
取消弹窗不会清除待确认数据，保存到表格后才移除对应待确认项；刷新或关闭页面会丢失它们。
旧版浏览器抓取缓存不再自动读取；可主动确认「恢复旧版缓存到待确认」后预览并核对令牌，
也可点击「清除旧版浏览器抓取缓存」直接删除而不读取其内容。
该按钮不删除曾经保存的浏览器账号配置；后者需用「清除浏览器草稿」单独清除。
只有主动点击「保存浏览器草稿」并确认才会把含凭证的草稿写入浏览器存储。
清除已保存草稿不会清空当前表格，也不会清除 GitHub 设置或远端配置。

## 可选 `.env` 托管

默认关闭。在「设置 → GitHub」勾选明文托管并保存后，点击同步才读取和更新目标**私有仓库**的 `.env`。
页面自动检测远端是否已有 `.env`，仅首次创建时弹出文件选择框；可导入已有文件，或选择用表格令牌创建。取消会停止本次同步，不写入文件或 Secrets。
已有远端 `.env` 时保留其他变量。私有仓库仍有权限、凭证泄露和明文历史风险。
不要将 `.env` 提交到本公开仓库。Pages 无法回写设备文件，调试时自行拉取私有仓库。

首次创建 `.env` 时需要保存后完整账号列表中的全部令牌，不只是本次新增账号的令牌。
已有 Actions Secrets 的值无法读回，不能用于反向生成 `.env`；可重新在表单填写、
主动选择完整模板，或取消明文 `.env` 托管，仅同步 Secrets。

## 保存一致性与重试

Pages 保存先校验账号、工作流和 `.env` 所需令牌，并准备 Secrets 加密数据。
校验失败不会发出文件或 Secrets 写入请求。

仓库文件通过一次 commit 更新，Secrets 则使用独立 API，两者不是原子事务。
旧 Secret 值无法读回，不能保证自动恢复被覆盖的凭证，因此不会尝试自动回滚或删除 Secrets。
文件已提交而任一 Secret 同步失败或响应无法确认时，页面会标为「保存未全部完成」，
列出已提交文件、已更新及未完成的 Secrets，保留当前账号草稿和填写的令牌供核对后重试；
草稿只在当前页面内，不保存到浏览器存储。关闭或刷新页面会丢失草稿。
所有选定操作完成后才显示已保存并重新加载账号列表。

已解锁的 PAT 可以直接用于重试；临时填入且未解锁保存的 PAT 可能需要重新输入。
相同文件内容不会产生新的 commit，同名 Secret 会再次创建或更新。
网络错误可能意味着服务器已接受请求但响应丢失，需先核对目标仓库状态。
本地服务模式使用私有后端 `/github-config`，其校验及写入顺序由该后端负责。

## 更新前端

直接维护本公开仓库 `cls4756/Newapi-checkin-pages`，不要从签到仓库覆盖新版账号表格。
签到后端仍在独立的配置仓库。本仓库不运行签到，也不提供 WebDAV / 实时查询的本地代理。
白名单打包会发布新增的设置和导出模块；测试、文档、账号文件和 Git 历史不会进入 Pages 产物。
Pages 工作流在打包前运行加密、配置导出与模拟 GitHub 保存测试。

## 其他按钮和兼容流程

- 「生成配置」只生成预览，不保存任何文件。仓库 JSON 不含凭证；旧版 JSON 可能包含令牌、
  Session 和登录信息。旧版简单格式仅支持基础 Session，无法表达系统令牌和高级选项时会拒绝复制。
  编辑、删除、导入或加载账号后旧预览失效，需重新生成；生成始终包含全部分页与筛选外的账号。
- Session / 登录信息只能通过旧版 JSON 或 WebDAV 保存；GitHub 同步会阻止丢弃这些字段。
- WebDAV 的地址、认证、文件名和 CORS 代理集中在「设置 → WebDAV」，保存设置后，主界面「WebDAV 同步」直接用当前表格覆盖目标 JSON。
  缺少连接信息时先打开对应设置，保存后继续同步；不再每次展开操作面板或确认普通上传。加载云端配置仍确认覆盖当前草稿。
  连接信息仅在主动保存设置时持久化；密码默认仅本页使用，勾选明文记住并确认后才保存。
  URL 使用实际目录，程序仅补充文件名，不猜测邮箱路径、不创建目录。代理只用于请求转发，
  生成的 `CONFIG_URL` 始终指向 WebDAV 本身。第三方代理能读取认证及配置，且不一定支持 PUT / PROPFIND。
- 签到后台优先使用指定配置文件，其次默认 `accounts.config.json`；未指定路径且默认文件缺失或为空，
  才尝试 `CONFIG_URL`，随后兼容 `NEWAPI_ACCOUNTS`。默认项目账号存在时，更新 WebDAV 不改变签到账号。
- 「实时签到查询」读取站点信息，不是 Actions 运行记录。需要配套本地服务和该本地来源的账号凭证草稿，
  只有 Secret 变量名无法查询；公开 Pages 会显示此限制，不请求不存在的代理。
- 「下载前端源码 ZIP」下载本公开仓库，不导出当前页面 DOM，因此不夹带已填写的凭证。

完整按钮对照及验证范围见 [界面检查记录](docs/UI-AUDIT.md)。

node tests/test_github_settings.js

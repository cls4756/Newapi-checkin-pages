# NewAPI Check-in Pages

独立的公开配置前端。这个仓库只托管网页，不包含签到程序、真实账号配置、
`.env`、PAT、Actions Secrets 或原私有仓库的 Git 历史。

## 启用免费 GitHub Pages

1. 将本目录作为全新的公开仓库推送到 GitHub，不要 fork 或公开原私有仓库。
2. 在公开仓库的 `Settings` → `Pages` 中，将 Source 设为 **GitHub Actions**。
3. 在 `Actions` 手动运行 **Deploy configuration UI to GitHub Pages**，选择默认分支。
4. 部署成功后打开 Pages 站点的 `/config_generator.html`，无需运行本地服务。

部署只发布 `scripts/build_pages.py` 中的静态文件白名单，不上传整个仓库。
首次部署前需先设置 Pages 来源；后续网页更新会自动部署。

## 修改私有配置仓库

1. 打开配置页的「保存到 GitHub」面板。
2. 填写原来的**私有配置仓库** `owner/repo`，不是这个公开前端仓库。
3. 输入仅授权私有配置仓库的 Fine-grained PAT，授予 Contents、Workflows、
   Secrets 的 Read and write 权限；组织仓库可能需要管理员批准。
4. 先「从 GitHub 加载」，再添加账号并填写新增或更新的令牌。
5. 确认保存，自动合并账号 JSON、更新两个签到工作流并加密上传账号 Secrets。

账号表格每行一个账号，支持搜索、分页和弹窗增删改；表格只显示令牌填写状态。
翻页和筛选不会缩小配置保存范围。编辑仅更新当前草稿，不自动保存到浏览器或 GitHub。
删除账号或修改站点 / 用户 ID 后，先确认已加载完整列表，再选择「替换账号列表」保存。

PAT 不写入网页源码、项目文件或浏览器存储。浏览器直连 GitHub API，
加密库随站点发布，不经过第三方代理。仅在自己控制的可信页面输入凭证。
远端私有仓库需要已有 `accounts.config.json` 和两个签到工作流。

## 添加账号、导入与书签

- 单账号导入在「添加账号」弹窗内：点击「从剪贴板填入」，或展开「手动粘贴单账号 JSON」。
  支持单个账号对象、只含一个账号的数组及只含一个账号的站点分组配置。
  导入只预填弹窗，检查后点击「保存到表格」，不会直接覆盖账号表或自动保存凭证。
- 同站点 URL + 用户 ID 的账号已存在时，会提示打开其编辑弹窗；缺省的变量名及凭证保留原值。
  同站点不同用户 ID 是不同账号，新账号未填写变量名时会分配独立名称。
- 主页面「批量导入 JSON」支持平铺数组和站点分组配置，默认合并并保留其他账号；
  只有明确选择并确认替换才移除草稿中的其他账号。全部账号校验通过后才更新草稿，
  变量名冲突或无效账号不会留下部分导入结果。替换后保存到 GitHub 需选择「替换账号列表」。
- 剪贴板权限不可用时，可在弹窗手动粘贴。关闭弹窗会清除其中的导入文本；
  剪贴板请求期间关闭或切换弹窗，不会把延迟返回的数据填入新的弹窗。
  书签代码无法自动复制时，也可在同一弹窗内手动复制，无需关闭弹窗或丢弃已填写内容。

站点抓取书签也已适配账号表。更新页面后，需要重新拖拽或复制新版书签：

1. 在已登录的 NewAPI 站点点击书签，先确认重新生成系统访问令牌的风险；旧令牌会失效。
2. 抓取结果复制为单账号 JSON；自动复制失败时，会提供手动复制方式。
3. 切回已有配置页，在「添加账号」中填入并检查，保存到表格，再统一保存到 GitHub。
   如没有已有草稿，也可在书签提示中选择打开新配置页。请勿重复抓取后忘记更新令牌。
   浏览器可能拦截新窗口，此时请手动切回或打开配置页。

新版书签不把令牌放进配置页 URL，不自动暂存或保存到浏览器，也不自动修改 GitHub。
旧版 `#bm=` 链接仍可接收：立即清除地址栏数据，只在当前页面保留待确认账号；
单账号预填弹窗，多账号可逐个确认或主动合并到草稿，按 URL + 用户 ID 区分。
取消弹窗不会清除待确认数据，保存到表格后才移除对应待确认项；刷新或关闭页面会丢失它们。
旧版浏览器抓取缓存不再自动读取；可主动确认「恢复旧版缓存到待确认」后预览并核对令牌，
也可点击「清除旧版浏览器抓取缓存」直接删除而不读取其内容。
该按钮不删除曾经保存的浏览器账号配置；后者需用「清除本地数据」单独清除。
只有主动点击「保存到本地」才会把当前草稿（可能包含明文凭证）写入浏览器存储。

## 可选 `.env` 托管

默认关闭，只有勾选并确认后才读取和更新目标**私有仓库**的 `.env`。
首次上传可主动选择设备上的 `.env` 模板；不选择则按表单中的账号变量创建。
已有远端 `.env` 时保留其他变量。私有仓库仍有权限、凭证泄露和明文历史风险。
不要将 `.env` 提交到本公开仓库。Pages 无法回写设备文件，调试时自行拉取私有仓库。

首次创建 `.env` 时需要保存后完整账号列表中的全部令牌，不只是本次新增账号的令牌。
已有 Actions Secrets 的值无法读回，不能用于反向生成 `.env`；可重新在表单填写、
主动选择完整模板，或取消明文 `.env` 托管，仅同步 Secrets。

## 保存一致性与重试

Pages 保存先校验账号、工作流和 `.env` 所需令牌，并准备 Secrets 加密数据。
校验失败不会发出文件或 Secrets 写入请求。

仓库文件通过一次 commit 更新，Secrets 则使用独立 API，两者不是原子事务。
旧 Secret 值无法读回，不能保证自动恢复被覆盖的凭证，因此不会尝试自动回滚或删除 Secrets。
文件已提交而任一 Secret 同步失败或响应无法确认时，页面会标为「保存未全部完成」，
列出已提交文件、已更新及未完成的 Secrets，保留当前账号草稿和填写的令牌供核对后重试；
草稿只在当前页面内，不保存到浏览器存储。关闭或刷新页面会丢失草稿。
所有选定操作完成后才显示已保存并重新加载账号列表。

重试需重新输入 PAT；相同文件内容不会产生新的 commit，同名 Secret 会再次创建或更新。
网络错误可能意味着服务器已接受请求但响应丢失，需先核对目标仓库状态。
本地服务模式使用私有后端 `/github-config`，其校验及写入顺序由该后端负责。

## 更新前端

在原项目使用 `python3 scripts/export_pages_repo.py --output ../新导出目录`，
将新导出目录内的白名单文件更新到本仓库。不要复制原仓库目录或 `.git`。
本仓库不运行签到；旧 WebDAV 和余额看板不具备本地代理能力。
